User guide

Langscape documentation

Use your own writing systems, test sound changes, and build syntax trees in your Obsidian vault.

Quick start

  1. On desktop Obsidian 1.15.0 or later, open Settings → Community plugins. Search for Langscape or use the official Obsidian listing, then install and enable it.
  2. Open the command palette and run Langscape: Create starter vault. This adds a Langscape Demo folder to your current vault without replacing existing demo files.
  3. Open Notes/Font demo.md or Notes/Tree demo.md inside the demo folder. Fonts, trees, and tables work without Java or Lexurgy. To run the demo recipe, set up Lexurgy first.

Custom fonts

Drop a .ttf, .otf, .woff, or .woff2 file anywhere in your vault. In Settings → Langscape → Fonts, use Rescan if needed, then use the pencil button to set a nickname such as gothic. Nicknames allow letters, numbers, underscores, and hyphens.

Part of a note

Use {nickname: text} in Live Preview or Reading view. You can also run Langscape: Insert custom-font text to open a font picker.

{gothic: 𐌰𐍆𐌰}

Whole note

Set langscape-font in the YAML frontmatter at the top of the note. Use the font name or its nickname.

---
langscape-font: gothic
---

Fonts don’t transliterate. Supply the characters your font is designed to display. Applying a font won’t turn Latin text into Gothic, Tengwar, or another script.

Lexurgy workbench

Set up the local engine

  1. Install Java 17 or later and extract the official Lexurgy CLI distribution. Langscape does not bundle or install Lexurgy.
  2. Open Settings → Langscape → Lexurgy. If Lexurgy isn’t detected, expand Advanced and set Lexurgy path to the extracted install folder, launcher script, or .jar. If Java isn’t detected, set Java path to the Java executable. With that field blank, Langscape checks JAVA_HOME or PATH.
  3. Click Test in the Lexurgy settings to verify that the engine runs.

Run and trace a change

Run Langscape: Create sound-change file or open an existing .lsc file. The editor highlights Lexurgy syntax and validates rules as you edit when Lexurgy is available. To try a minimal example, replace the template with:

First:
  a => b
  • In the Test bench, enter one word per line, then click Run. For the example above, a becomes b. Use From rule and Stop before to test just part of a file.
  • Check Trace applied rules before running. Select result rows or their checkboxes to see which rules changed each word.
  • Click Docs to open the Lexurgy manual in a separate Obsidian tab, or read the manual on the web.

Recipe automations

Run Langscape: Create recipe to make a .recipe file. Recipes use Lexurgy to batch-transform notes into copies.

  1. Choose an Input folder. Only Markdown notes directly in that folder are read, not subfolders.
  2. In the Property menu, choose Note title (filename) or a text property. Title mode changes the copy’s filename, not its contents or headings. Property mode keeps the filename and changes only the selected frontmatter value, such as word: apa. Notes without a nonblank text value for that property are skipped.
  3. Use Add sound changes… to select .lsc files. Files run from top to bottom; you can disable individual rules in each file.
  4. Choose a different Output folder and click Run recipe.

Use a dedicated output folder. Source notes are untouched, but a run replaces any Markdown note at a generated output path, including manual edits. Other output files are left alone. If two inputs would generate the same filename, the run stops rather than picking one.

Syntax trees

Put the markup on its own Markdown line, with blank lines around it and no code fence. Start with one root label, put its children in parentheses, and separate siblings with commas:

{tree: S(NP(I), VP(V(see), NP(stars)))}

Use an inline font span as a label, for example {tree: NP({gothic: 𐌰𐍆𐌰})}. An empty label is written "".

  • Run Langscape: Insert syntax tree to start with {tree: ""}, or edit the markup directly in Source mode.
  • In Live Preview, click a label to rename it. Hover over a node for controls to add a child or delete a node. Drag a non-root node to move or reorder its subtree.
  • Use the alignment button above the tree to switch between centered and left-aligned trees.

Merged table cells

In a Markdown table, select at least two cells and run Langscape: Merge table cells. To unmerge, put the cursor in the merged cell and run Langscape: Split merged table cell. The merge joins nonempty text into the top-left cell; splitting leaves that text there and clears the other cells.

Write markers by hand

  • < joins the cell to the one immediately to its left.
  • ^ joins the cell to the one immediately above.
  • > joins the cell to the one immediately to its right. Live Preview may rewrite this in the usual left/up form.

Markers occupy the whole cell. Each merge must form a rectangle with one content cell and cannot cross the header/body boundary. This example makes one cell that spans both body rows and columns:

| Form | Gloss |
| --- | --- |
| apa · father | < |
| ^ | < |

The note stays Markdown. Apps that don’t support these merges may show the markers as text.

Troubleshooting

  • Font missing or characters look wrong: Rescan vault fonts, confirm the nickname, and check that the font covers the characters you typed. Test in Live Preview or Reading view.
  • Lexurgy won’t run: Check both paths under Advanced, then use Test. If the connection works but a rule fails, check the validation message in the .lsc editor.
  • Recipe skipped a note: Check that it is directly in the input folder and, in property mode, that the chosen YAML property contains nonblank text rather than a number or list.
  • Tree or table markup is still visible: Switch from Source mode to Live Preview or Reading view. Check that the tree is on its own line or that the merge markers form a valid rectangle.

Privacy

Langscape has no telemetry. It checks local paths, including paths outside your vault, for Java and Lexurgy. Rules and test words go to a local Lexurgy process, not an online service.

The in-app Docs tab fetches public manual pages from lexurgy.com and examples from raw.githubusercontent.com. Vault fonts load locally; older fonts configured with a URL still load from that host.
